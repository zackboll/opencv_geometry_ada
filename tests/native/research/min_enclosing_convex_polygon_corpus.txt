# Frozen corpus for the opt-in minEnclosingConvexPolygon research runner,
# scripts/run_min_enclosing_polygon_research.py. Nothing in the default
# build, the AUnit suite or CI reads it.
#
# Each case is a block of lines:
#
#   case NAME            lowercase letters, digits and underscores
#   origin TEXT          where the input comes from; may repeat
#   k INT                the polygon vertex count passed to OpenCV
#   depth f32|i32        optional: CV_32FC2 (the default) or CV_32SC2 input
#   points X:Y ...       binary32 points, each coordinate as the 8 hex digits
#                        of its IEEE 754 bit pattern; may repeat
#   optimum VALUE WHY    optional: the exact minimum area, with its proof
#   expect FAMILY KIND   optional: an observed outcome; may repeat
#   end
#
# Generated inputs were frozen with the runner's freeze subcommand, so the
# bit patterns, not libm or the libstdc++ distributions, define them.
#
# Expectation families, all observed on Linux x86-64 with g++ 14.2.0:
#
#   released      exact tags 4.13.0, 4.14.0 and 5.0.0, as installed release
#                 libraries and as the unmodified tagged source compiled into
#                 the probe with sanitizers and library assertions
#   pr30111-base  opencv/opencv 5.x 20e367198c7adde8f1efc0f525256b1e15798024,
#                 the base of upstream PR 30111, built the same two ways
#   pr30111-head  01f4d0e5da231d00c1eca735a0880b492a69fdde, the PR's head
#
# Outcomes are those the runner reports: polygon, polygon_nonminimal,
# polygon_invalid, empty, cv_exception and crash. An expectation records what
# happened, not what should happen; polygon means that the runner's checks
# found no fault, not that the polygon is minimal.
